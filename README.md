# once-upon-a-paper

Construct your related work or convince you to pivot.

Given a proposed abstract, `ouap` scans tens of thousands of papers from major AI conferences using an LLM and returns the ones that are related — each with a short reason explaining why. The output is a ready-to-use `.bib` file, a structured `.json` report, and a prose `report.md` synthesizing the related work landscape.

The LLM only outputs bib keys (not full citations), which are then resolved against a local database. This keeps generation tokens minimal and eliminates hallucinated references.

## Supported Venues

| Source | Venues |
|--------|--------|
| ACL Anthology | ACL, EMNLP, NAACL, EACL, COLING, Findings |
| Semantic Scholar | NeurIPS, ICML, ICLR, AAAI, IJCAI |

## Supported Models

OpenAI (`gpt-4o-mini`, `gpt-4o`, `gpt-4.1-mini`, `gpt-4.1-nano`), Anthropic (`claude-sonnet-4-20250514`, `claude-haiku-4-20250414`), Google Gemini (`gemini-2.0-flash`, `gemini-2.5-flash-preview-04-17`, `gemini-2.5-pro-preview-03-25`), and local HuggingFace models.

## Install

```bash
conda create -n ouap python=3.11 -y
conda activate ouap
pip install -e ".[openai,anthropic]"
```

Set your API key:

```bash
export OPENAI_API_KEY="sk-..."
# or
export ANTHROPIC_API_KEY="sk-ant-..."
# or
export GOOGLE_API_KEY="..."
```

Or use a `.env` file (see `.env.example`):

```bash
ouap --env-file .env scan -a abstract.txt
```

## Usage

### 1. Fetch paper data

Download papers into the local cache. This only needs to be done once (data is reused across scans and refreshed every 30 days).

```bash
# Fetch all venues, 2016-2026
ouap fetch

# Specific venues and year range
ouap fetch --venues ACL,EMNLP,NAACL,EACL,COLING,Findings,NeurIPS,ICML,ICLR,AAAI,IJCAI --years 2010-2026
```

### 3. Prepare your abstract

Create a plain text file with your paper's abstract (or thesis summary, research proposal, etc.). The file is not tracked by git.

```bash
# Write your abstract to a .txt file
cat > abstract.txt << 'EOF'
We investigate how identity framing in LLM instructions shapes model
behavior and internal representations. By systematically varying the
personas embedded in system prompts...
EOF
```

### 4. Scan for related work

```bash
# See cost estimate first (no API calls to LLM)
ouap scan -a abstract.txt --dry-run

# Run the scan
ouap scan -a abstract.txt -o results

# Narrow the scope
ouap scan -a abstract.txt --venues ACL,EMNLP --years 2022-2025 -m gpt-4.1-nano

# Read abstract from stdin
cat abstract.txt | ouap scan -a - -m gpt-4o-mini --yes
```

### 5. Output

After scanning, three files are written to the output directory:

**`related.bib`** — BibTeX entries for all matched papers, ready to drop into your LaTeX project.

**`related.json`** — Structured report with categories, relevance scores, and reasons per paper.

**`report.md`** — Human-readable prose report synthesizing the related work landscape. Five sections: novelty risk assessment, competitive landscape, methodological context, supporting evidence and gaps, and a prioritized reading order. Generated by separate LLM calls so each section is focused.

Use `--skip-categorize` for a flat list without categories, or `--no-report` to skip report generation.

| Option | Short | Default | Description |
|--------|-------|---------|-------------|
| `--abstract` | `-a` | required | Path to abstract text file, or `-` for stdin |
| `--venues` | `-v` | `all` | Comma-separated venue codes |

| `--batch-size` | `-b` | `50` | Papers per LLM batch |
| `--dry-run` | | | Show cost estimate only |
| `--yes` | | | Skip confirmation prompt |
| `--skip-categorize` | | | Skip categorization, output flat list only |
| `--no-report` | | | Skip report generation (Phase 3) |

## How It Works

1. **Fetch** downloads paper metadata (title, abstract, authors, bib entry) from ACL Anthology and Semantic Scholar, storing it in a local SQLite database.
2. **Scan (Phase 1)** sends your abstract alongside batches of ~50 candidate papers to the LLM. The LLM returns only the bib keys of related papers with a brief reason (<20 words). Returned keys are validated against the batch to discard hallucinated references.
3. **Categorize (Phase 2)** sends matched papers back to the LLM with a detailed taxonomy prompt. Each paper is assigned one of seven categories (OVERLAP, CONTRA, SAME_PROBLEM, etc.) and a 1–5 relevance score.
4. **Report (Phase 3)** makes five separate LLM calls — one per report section — to synthesize the categorized papers into actionable prose: novelty risk, competitive landscape, methodology context, supporting evidence, and a reading order.
